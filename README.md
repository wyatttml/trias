## ✨ 亮点

| | |
| --- | --- |
| 🏛 **三权分立** | 方案、执行、验收由三个模型分担；执行与验收来自不同厂商，验收不会给自己放水。 |
| 📜 **手册即法律** | 每段工作一份手册，写死「要做 / 不做 / 通过线 / 降级路径」。验收的遗留项自动追加进下一段手册，法律会生长。 |
| 📏 **程序说了算** | 测试、冒烟、密钥扫描由脚本跑出结果；验收员写了「通过」但程序结果没过，脚本直接改判返工。 |
| 🪜 **返工四级** | 同一项第 1 次失败执行模型修，第 2 次先出检查单再修，第 3 次验收模型亲修，第 4 次交方案模型。不会无限循环，也不会一直让同一个模型撞墙。 |
| 🩺 **先分诊再返工** | 只有程序行为错才返工；成品质量进「调优清单」由人改提示词和模板；网络故障不算轮次，自动重跑。 |
| 🌙 **没人在也能跑** | 可选的值守脚本不用 AI、常驻后台：出事起一次性短会话按故障说明处理，返工单夜里照草稿办。 |
| 📮 **少打扰** | 只有几类事一定等人：新开付费服务、删数据、改范围、改密钥配置、返工用完、额度用完。其余 10 分钟没人答就按推荐办。 |
| 🔌 **每一块都能换** | 换模型、换通知渠道、换语言、换成非代码项目，都只改一个函数或一个文件。 |

## ⚡ 接入

在你的项目根目录二选一：

| | 只装核心（默认） | 全套（`--full`） |
| --- | --- | --- |
| 命令 | `curl -fsSL …/install.sh \| bash` | `curl -fsSL …/install.sh \| bash -s -- --full` |
| 装什么 | 编排脚本、程序检查、计数定级、通知、`run.sh` 检查，开工 / 返工 / 验收 / 检查单 / 亲修五份提示词，规则卡与模板 | 核心 + 值守、审稿包循环、读大文件拦截钩子、两个只读子代理 |
| 适合 | 你人在电脑旁，卡住了收邮件处理 | 想让它通宵跑，或对话上下文总是被大文件撑爆 |
| 后台进程 | 1 个（`run.sh`） | 2 个（再加 `duty.sh`） |

两种都只往项目里拷文件：已存在的一律跳过，往 `.gitignore` 补上 `.env` 和 `运行数据/`。不创建 `.env`，不碰你的代码，不改你的 `.claude/settings.json`（钩子要加的那一段会打印出来）。

然后：

1. **立法**：让方案模型照 `手册/_模板_Sn_子阶段名.md` 写 `手册/S1_xxx.md … Sn_xxx.md`，并把子阶段填进 `项目状态.md`。
2. **接检查**：把 `pipeline/checks.sh` 里的测试命令换成你的，手跑一次 `bash pipeline/checks.sh S1`。
3. **开跑**：

```bash
nohup caffeinate -dims bash pipeline/run.sh >> 运行数据/pipeline/日志/nohup.out 2>&1 &
```

前置条件：已登录的 [Codex CLI](https://github.com/openai/codex) 和 [Claude Code](https://github.com/anthropics/claude-code)。Linux 去掉 `caffeinate -dims`。要停下：`touch 运行数据/pipeline/停止`。手册没写完也可以先开跑，它会等手册、写好了自己接着跑。完整清单见 [DESIGN.md 第 17 节](./docs/DESIGN.md#17-复刻清单照着做约一小时)。

## 🏛 为什么是三权分立

一个模型从头干到尾，等于让同一个人立法、执法、判案。Trias 把三种权力拆给三个角色，并让它们互相够不着对方的手：

| 权力 | 谁 | 产出 | 被谁制衡 |
| --- | --- | --- | --- |
| **立法** | Fable（方案模型） | 每段手册：要做、不做、通过线、降级路径；返工第 4 级的裁决 | 不碰代码；通过线必须能用程序量出来 |
| **执行** | GPT · Codex CLI | 代码、测试、冒烟脚本、交付说明 | 不改流水线、不碰 Git；唯一能改的状态是交回「待验收」 |
| **司法** | Claude Opus | 三选一结论：通过、返工、需决定；返工第 3 级亲修 | 程序结果没过就判不了通过；返工单只许指到本段手册 |
| **主权在民** | 你 | 红线上的最终决定 | 10 分钟不回，非红线事项按推荐自动执行 |

和其他做法比：

| | 单模型从头干到尾 | 多智能体框架 | **Trias** |
| --- | --- | --- | --- |
| 谁来验收 | 它自己 | 框架内的另一个角色 | **另一家厂商的模型，程序结果没过它也判不了通过** |
| 状态存在哪 | 对话上下文 | 框架运行时 | **磁盘上的 Markdown 进度表，重启可接管** |
| 你怎么介入 | 盯着终端 | 看框架界面 | **收邮件，点「按推荐办」** |
| 没人在时 | 停着等你 | 看框架 | **值守脚本起一次性短会话处理，返工单照草稿办** |
| 依赖 | 编码工具本身 | Python 包与运行时 | **bash + python3 标准库** |
| 换一个模型 | 换工具 | 改适配层 | **改一个 shell 函数** |

## 🪜 返工四级

计数按「项」走：测试、冒烟的每一步、回归的每一件各记各的真失败次数，当前没过的项里次数最多的就是级别。

| 级别 | 谁修 | 怎么修 |
| --- | --- | --- |
| 1 | 执行模型 | 照验收结论（或值守起草的返工单）修 |
| 2 | 执行模型 | 先开一个只读会话写检查单，找出「上次修了为什么还没过」，再照单修 |
| 3 | 验收模型 | 亲自只修这一项，执行模型不碰 |
| 4 | 方案模型 | 停下等它：改手册后写「返工：…」，或判「通过」 |

返工四级只管程序行为错。成品写得平庸、模板不好看这类问题进验收结论的「调优清单」，通知里会提醒「有 N 条要改提示词 / 模板」，由你或方案模型直接改，不归执行模型。

## 🧯 踩坑博物馆

Trias 的每一条规则，都对应一次真实事故。挑三件：

> **🌀 验收写了「通过」，冒烟其实是 FAIL。**
> 验收模型读交付说明读得太顺，没对上程序结果。
> → 现在：程序结果没过，脚本直接改判返工，谁写「通过」都不算。

> **🔇 改了一行日志，流水线半夜静默停了。**
> 脚本开了 `set -u`，新加的一行引用了没赋值的变量，进程悄悄退出，`bash -n` 和 shellcheck 都查不出。
> → 现在：脚本退出必报警；改完先跑 `run_sh_check.py`，专抓「引用了但从没赋值」的变量。

> **💸 额度用完，流水线一遍遍白跑。**
> 模型返回额度用完，流水线当成普通失败，10 分钟后自动按推荐「继续」，再撞一次。
> → 现在：认出额度用完的字样就一直等人，不自动继续。

另外十几件见 [DESIGN.md 第 14 节](./docs/DESIGN.md#14-踩过的坑真实事故已在脚本里修)。

## 💡 设计原则

1. **用文件交接，不用聊天交接。** 手册是法律，验收结论是判决书，进度表是唯一事实。模型之间也不互发消息。
2. **脚本是唯一的状态推进者。** 模型只干活，不推进流程。
3. **通过线只有两条。** 和上一版并排看不退步；程序确定项全过。不拿数字升降当理由。
4. **先分诊再动手。** 程序错返工，成品质量调提示词，网络故障重跑，风格只提醒。
5. **流程增加人的操作而不提升成品，就是自嗨。** 每加一个确认点前先问：这一步让成品更好，还是只让流程更长？

<details>
<summary><b>❓ 常见问题</b></summary>

**为什么不让一个模型从头干到尾？**
自己验收自己会放水。换一家厂商的模型验收，并且程序结果没过它也判不了通过，判断才可重复。

**为什么不加更严的审核？**
真实经验是越重越假：每段写网页自动点击检查、重跑前序阶段，验收时间翻倍，成品没有变好。先把通过线写得可量。

**执行模型为什么不跑全量测试？**
全量由流水线在它自己的环境里跑一次，结果以它为准；执行模型再跑一遍只是让流水线多等。返工时按「改动波及面」表补跑相关的。

**夜里出事了怎么办？**
装了值守，它会起一个一次性短会话照 `停了怎么办.md` 处理，能恢复就恢复，结果发邮件给你。付费、删数据、改范围、改密钥仍然留给你。

**能用在非代码项目上吗？**
能。把 `checks.sh` 换成格式校验、字数、必含章节这类能量出来的检查，冒烟改成「真实产出一件成品」。

**执行模型想换成 Claude、验收换成 GPT 呢？**
改 `run_codex` 和 `run_claude` 两个函数即可，提示词不用动。见 [DIY 替换表](./docs/DESIGN.md#16-diy-替换表)。

**能并行吗？**
可以开多条 git worktree 并行，但编排脚本会翻倍，合并类事故也都出在这里。建议先单线跑通。要点见 [DESIGN.md 第 15 节](./docs/DESIGN.md#15-进阶两线并行可选第一版不要做)。

**Windows？**
用 WSL。

</details>
