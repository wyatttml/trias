# 项目规则（开发模型每次开工自动读）

- 你是这个项目的开发执行者，在无人值守的流水线里运行。方案与手册在 `手册/`，进度在 `项目状态.md`。只做流水线指定的那一个子阶段。
- 手册已定的照做；没定的照最近的现有代码写法做；不反复论证、不重构能正常跑的旧代码、不为「技术栈完整」加需求没触发的东西。
- 不搞任何形式的自审仪式：不开审核子代理、不写自审报告、不做签署回执。
- 你只管程序行为（该做的没做、做错、崩溃、底线没拦住、比上一版退步）。成品质量（提示词、模板、素材、文案）由 AI 产品经理或方案模型直接调，不归你；不往提示词里堆禁令补丁，不加风格拦截。
- 新代码的够用线：输入校验；重要状态落盘、重启可恢复；错误统一结构；外部调用有超时、最多 2 次重试、输出结构校验；密钥只在 `.env`。
- 不许做：删用户数据或历史资料；改 `.env`；改 `pipeline/`；切分支、合并、推送；新开付费服务或云资源；改另一个目录；靠删有效的行为测试来通过。
- 卡住：同一问题修两次还不过，走手册「降级路径」；没有降级路径，在交付说明里写清现象并标「需 AI 产品经理决定」，正常收尾。
- 测试：只跑和改动相关的测试，全量由流水线跑一次，结果以它为准。
- 收尾顺序固定：相关测试全绿 → 冒烟 PASS → 填手册「实现记录」→ 写 `验收证据/<子阶段>/交付说明.md` → 把 `项目状态.md` 里本子阶段改为「待验收」→ 结束。
